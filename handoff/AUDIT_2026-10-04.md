## Reproduced blockers: green suites are incomplete

### B-001 — natural Global playback end uses the wrong queue

Reproduction at candidate exact head, first-run storage, desktop 1440x900:

1. Open canonical preview with `?skip-onboarding=1` for audit only.
2. Play Discover → Hits today → Continuum (`a101`).
3. Global queue persists `[k101,a101,g101,s101,m102,n101,t101,k105]`.
4. Let the actual 32-second recording finish naturally; do not dispatch a fake ended event or depend on seek timing.
5. Actual next track becomes Half Awake (`a102`), not Open Circuit (`g101`). `rondo-prototype-v2.session.selectedTrackId` changes to `a102`; `globalSession.currentTrackId` remains `a101`.

The audio `ended` event was observed; no page error occurred. A successful short button-path suite therefore does not prove correct end-to-end playback. Source explains the split: `src/app.js` audio callback calls `handleTrackEnd()` with the singleton artist `currentQueue()`, while `playbackContexts.js` intercepts on-screen Previous/Next click paths. Media Session Previous/Next also calls legacy `changeTrack()` directly; treat that as a source-identified coverage risk until separately reproduced.

**Acceptance:** natural end, media-key next/previous, on-screen controls and Song Room all use the active logical queue, update the same selected ID/index/position, preserve the inactive session and apply an explicit queue-end/repeat policy. Add regression coverage through real media events plus deterministic domain-command tests. No app fix was made this round.

### B-002 — one-result Discover search silently broadens the queue

1. Fresh Discover, search `Night Transit`.
2. Exactly one track result appears: `k101`.
3. Play it. Queue label says `Discover search`, but the stored queue contains 20 tracks including `a101`, `g101`, `s101`, `a102`, `k102` and unrelated shelves.

`queueFor()` in `playbackContexts.js` falls back to all visible Discover/playable items when the initiating source has fewer than two results. This violates the source-bounded queue contract. A one-song source should remain one song; extending discovery requires an explicit labeled opt-in, not a silent fallback.

**Acceptance:** test zero/one/many-result Search, Sounds, Library and Release sources, current-item membership, queue-end behavior and reload. No source changes this round.

Machine-readable probe observations are in [audit-evidence/2026-10-04/](audit-evidence/2026-10-04/). They are local diagnostic observations, not CI outputs. Initial accelerated seek probes were inconclusive and are not used as defect evidence; the natural-end observation above is the valid reproduction.

## Repository and engineering findings

- **B-003: main dependency risk remains.** `playwright` below 1.55.1, GHSA-7mvr-c777-76hp, browser-download certificate verification. It is a development-tool supply-chain risk, not evidence of production account compromise. Candidate lock resolves the fix; main has not integrated it. Do not report repo-wide zero vulnerabilities. Remediate deliberately in a code/dependency round.
- **F-001: legacy Discover is not actually caller-free.** `src/app.js` imports `renderDiscoverView()` and calls it inside `renderActiveSurface()`. The later route/policy layer replaces presentation. Remove or migrate callers with regression tests; do not delete the export merely because old docs called it dormant.
- **F-002: observer/controller debt.** Several controllers watch body/subtrees and bridge state via synthetic clicks, DOM metadata and localStorage. `discoveryHub.js` is a single minified line with terse names. Preserve behavior first, then restore readable source and consolidate explicit route/store/audio intents in a controlled migration.
- **F-003: persistence target exceeds current shape.** The dual-session key does not directly retain independent global position/repeat/index fields. Singleton/route state supplies parts of behavior. Production requires first-class versioned sessions and restoration tests, not a claim that target schemas are already implemented.
- **F-004: candidate CI is branch-specific.** QA currently triggers on `rondo-v031-user-ready`, whereas main Pages deploys without equivalent test gating. Before an accepted merge, design/enforce main/PR/post-merge QA so merge cannot bypass the quality contract. Current main updates are docs-only; no runtime release certificate follows from Pages deployment.
- **F-005: onboarding specification differs from runtime.** Prototype is four local-profile steps, email validation, at least three genres and two artists; production doc describes up to seven account/preferences steps and at least five artists with uncertainty paths. Mark planned vs implemented, decide first-listen friction before editing. Email currently creates no authenticated account.
- **F-006: canonical continuity was stale.** Main docs named `742abac`/earlier CI/evidence instead of final integration head and linked some latest captures to historical `513d538`. Reconciled here. PR #9 rejection was missing from canonical main handoff; now durable.
